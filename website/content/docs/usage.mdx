---
title: Usage
description: The ways to start mdd, from a file, a folder, or standard input.
---

```sh
mdd                 # pick from the Markdown files in the current repo or folder
mdd README.md       # preview a file
mdd docs            # pick from the Markdown files in a folder
cat notes.md | mdd  # preview standard input
```

## Preview a file

`mdd FILE` opens one file. It opens any text file. If the name doesn't end in `.md` or `.markdown`, mddog shows it as Markdown anyway, with a short notice.

mddog opens one file at a time. If a name has spaces, put quotes around it. If a name starts with `-`, write `./-name.md` or `mdd -- -name.md`.

mddog opens only local files. To preview a file on the web, download it first:

```sh
curl -sL https://example.com/README.md | mdd
```

If you mistype a name, mddog suggests a close match in the same folder.

## Pick a file

With no file, `mdd` shows the [file list](/docs/features#file-list). It lists every `.md` and `.markdown` file in the current git repo, or in the current folder when you're not in a repo. `mdd FOLDER` lists the files in that folder instead.

## Read standard input

When you pipe text into `mdd`, it previews that text:

```sh
cat notes.md | mdd
gh pr view 123 --json body -q .body | mdd
```

When standard input isn't a terminal, `mdd` with no file always reads it, even in a script. Empty input stops with an error. `mdd -` also reads standard input. If you run `mdd -` in a terminal with nothing piped in, type the Markdown and press `Ctrl-D` to open it.

A preview of standard input doesn't reload, and `e` can't edit it.

## Options

| Option | Does |
|---|---|
| `-h`, `--help` | Show the help |
| `-V`, `--version` | Show the version |
| `--` | Treat every argument after it as a file name |

On an error, `mdd` prints what went wrong and exits with code 2.

Inside the preview, press `?` to see the [key bindings](/docs/keys).
